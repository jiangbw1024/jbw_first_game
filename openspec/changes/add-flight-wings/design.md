# Design

## Context

玩家位移已经采用服务器权威模拟，客户端只上传方向、朝向、冲刺和“本帧是否按下跳跃”；装备由商店服务以可靠的玩家→物品账本保存，并通过广播和新玩家快照重放收敛。当前账本只有一个手持槽，商品表也默认所有商品都是手持武器。

项目没有真实货币、背包消耗或存档，商店价格只用于界面展示；角色外观由 `Goods` 常量中的基础几何生成。无头测试已经覆盖购买距离、非法商品、加入重放和玩家移动，因此翅膀应复用这些边界，而不是另建一套购买或同步通道。

## Goals / Non-Goals

**Goals:**

- 将装备扩展到独立的手持槽和背部槽，使翅膀与枪械可以同时存在。
- 用同一份商品常量驱动上海店、服务端校验、联机外观和飞行能力判断。
- 以明确的服务器状态机实现二次起跳、上升、缓降、落地和死亡复位。
- 让远端玩家看到与权威飞行状态一致的翅膀姿态，并让本地玩家获得 HUD 反馈。
- 用无头探针覆盖单机、购买和联机重放路径。

**Non-Goals:**

- 不实现体力、燃料、耐久、冷却、空战武器、飞行敌人、飞行专属地图或存档。
- 不重做现有商店为购买/拥有/装配多级流程；本次仍是“购买即装备到对应槽位”。
- 不引入外部美术资源、骨骼动画或第三方依赖；翅膀沿用程序化几何。
- 不增加世界高度边界或防止玩家飞出地图的硬限制。

## Decisions

### 1. 装备账本按槽位保存

商店服务把每个玩家的装备保存为手持槽与背部槽两个整数，并广播“玩家标识 + 手持物品 + 背部物品”的可靠快照。购买商品时按商品声明的槽位只更新对应槽位，因此购买翅膀不会覆盖枪械。

替代方案是继续使用单个物品标识并让翅膀占用手持槽；这会直接违反“翅膀与武器同时存在”的目标，也会让后续加入护甲、背包等槽位时再次重写协议。多槽位结构只增加一次迁移成本。

现有测试使用的“查询玩家当前装备”入口可以保留为手持槽查询，另外增加按槽位查询接口，避免破坏已有武器验收语义。

### 2. 商品表声明槽位，外观组件按槽位消费

商品增加明确的槽位字段和显示名。槽位为手持的物品继续交给现有手持外观组件；翅膀使用新的背部外观组件，从同一份商品几何数据生成左右对称翼片。服务端只接受槽位与购买入口匹配的商品，避免把枪械写进背部槽。

替代方案是按商品编号在多个位置写特判。编号特判会让商店、服务端和玩家脚本各有一份“哪些是翅膀”的真相，后续加第二件背部装备时必然分叉。

### 3. 飞行是服务器上的显式状态机

玩家保存“翅膀是否已装备、本次离地是否还可用二次激活、当前是否飞行、跳跃键是否持有”四类状态。首次跳跃仍使用现有跳跃速度；在空中再次收到跳跃按下且本次离地尚未激活时进入飞行。飞行中：

- 持有跳跃键时，垂直速度向正的上限逼近；
- 松开跳跃键时，垂直速度向较慢的下降上限逼近；
- 普通重力不直接作用于飞行状态；
- 水平移动沿用现有输入方向、冲刺和加速度约束；
- 接触地面后退出飞行并恢复下一次激活机会。

替代方案是给玩家持续向上的力或直接使用“无重力”。持续力难以形成稳定的按住/松开手感，无重力则会在松手后让玩家悬停，不符合缓降目标。

### 4. 输入 RPC 同时传按下与持有状态

输入包保留一次性“跳跃按下”用于状态切换，并新增“跳跃当前是否按住”用于飞行高度控制。服务器继续校验发送者身份，方向做长度限幅，布尔状态只作为意图，不信任客户端上报速度或位置。界面捕获输入时同时清除按下和持有状态，防止关闭界面后继续上升。

替代方案是客户端在飞行中持续发送垂直速度；这会直接破坏服务器权威，也容易被修改客户端利用。

### 5. 飞行视觉状态使用可靠的状态切换广播

玩家位置和旋转继续由现有连续同步负责。翅膀的“展开/收起”是低频离散状态，在服务器切换飞行状态时通过可靠 RPC 广播给所有端；外观组件只根据该状态插值翼片角度。装备变化仍由商店服务的可靠装备快照负责。

替代方案是把飞行布尔值塞进不可靠连续同步。丢包后远端翅膀可能永久停留在错误姿态，和现有装备同步避免的问题相同。

### 6. 第一人称隐藏自身背翼，HUD 承担本地反馈

本地第一人称角色的身体本来就隐藏，背翼若贴近相机可能遮挡视野，因此本地不绘制自身背翼；本地玩家通过 HUD 查看“可起飞/飞行中”状态。远端玩家角色保持可见背翼，并在飞行状态切换时播放展开/收拢插值。

## Risks / Trade-offs

- [装备快照格式从单物品变成双槽] → 本次没有存档兼容压力；同步修改主机、客户端、重放和既有商店测试，避免新旧结构混用。
- [二次跳跃与现有“只传按下”输入协议耦合] → 在同一次 RPC 中同时传按下和持有状态，并用界面锁、死亡和落地统一清空，减少状态残留。
- [角色贴地判定可能在一帧内反复切换] → 飞行状态只在服务器物理模拟后、确认接触地面时结束，并用“本次离地已激活”标记阻止同一段滞空重复起飞。
- [无限上升会削弱丧尸威胁] → 本次明确接受该平衡取舍，后续可用体力、燃料或高空气流限制扩展，不需要改输入语义。
- [远端翅膀动画依赖状态广播顺序] → 装备更新与飞行状态都使用可靠消息，且玩家节点加入后会重放装备快照；动画状态以服务器最新广播为准。
- [本地隐藏背翼会降低装备反馈] → HUD 明确显示翅膀状态，商店购买成功提示仍保留，避免玩家不知道装备是否生效。

## Migration Plan

1. 先扩展商品表和装备账本，同时让旧手持商品仍按原行为工作。
2. 加入背部外观与槽位化应用逻辑，再接入商店购买反馈。
3. 加入飞行输入、服务器状态机和可靠视觉状态广播。
4. 更新无头测试，先跑现有商店/装备/输入回归，再跑新增翅膀飞行与联机重放探针。
5. 回滚时可移除翅膀商品和背部槽接入；现有手持武器数据仍能按旧槽位读取，不涉及持久化迁移。
